# 极地航线决策推演系统 · PolarRoute

浮冰海域科考船的可交互式航线决策界面：在动态海图上推演船体位置、浮冰漂移、风向、能见度、
燃料余量与通信覆盖；通过拖动航路点、调整航速、设置等待窗口来对比方案，系统实时给出 ETA、
补给窗口达成情况与跨冰带 / 通信盲区的连锁影响；支持暂停、从任意历史节点重新推演，
以及在通信恢复后合并离线期间的有效操作。

## 运行

纯静态前端，无构建、无依赖：

```bash
# 任选其一
open index.html          # macOS
python3 -m http.server   # 然后访问 http://localhost:8000
```

文件结构：

- `index.html` — 界面骨架（顶栏 / 左仪表 / 海图 / 右分析 / 时间轴）
- `styles.css` — 深色航海控制台主题
- `app.js` — 确定性环境模型、航路推演器、Canvas 渲染、事件溯源历史、离线合并

## 海图要素

- **船体**（青色三角）沿计划航线运动，绿色尾迹为已航轨迹
- **浮冰**（130 块不规则多边形）按各自漂移速度 + 环流确定性运动
- **高风险冰带 B1/B2**（红色椭圆带）随时间漂移，颜色越红风险越高
- **雾团**（灰白色径向区域）缓慢移动，局部压低能见度
- **通信覆盖圆**（青色虚线）——圆外即通信盲区
- **风向羽**按当时风向 / 风速旋转；右下角罗经同步指示
- **出发港**与**补给站 · 极地 3 号**（补给窗口 T+16h ~ T+28h）

## 交互

| 操作 | 方式 |
| --- | --- |
| 查看航段逐小时风险 | 点击任意航段，右侧「风险」页展示未来 6 小时冰况、能见度、风、在线状态 |
| 修改航线 | 拖动航路点（穿陆 / 进入冰带核心 / 改动已越过航路点会被拒绝） |
| 等待窗口 / 段速 | 双击航路点，设置等待小时数与该航段计划航速 |
| 改变全局航速 | 左侧「计划航速」滑块（4–18 kn） |
| 推演控制 | 开始 / 暂停、4 档模拟速率（1 分/秒 ~ 1 时/秒）、+1 小时快进、重置 |
| 重新推演 | 时间轴节点或「推演历史」面板中点击任意历史节点，回到该时刻产生平行分支 |
| 离线操作 | 盲区内的改线 / 变速 / 等待进入队列；恢复覆盖后自动逐项校验并合并 |

## 模型说明

- 世界坐标 1 单位 = 0.25 nmi，全图约 250 nmi；默认航线约 231 nmi
- **有效航速** = 计划航速 ×（1 − 0.62×冰风险）× 低能见度折减
- **油耗**随航速与冰况 / 能见度上升；抵达补给站且在窗口内补至 92%
- 环境（风、冰带、浮冰、雾）全部由任务相对时间的确定性函数驱动，
  同一历史节点重新推演结果可复现
- 改线后按船体世界坐标重新投影到新航线，避免航程跳变

## 连锁影响卡片

「连锁影响」页自动识别并以「原因 → 结果」链条展示：

- 穿越高风险冰带 → 减速 → ETA 后移 → 可能错过补给窗口
- 错过 / 早于补给窗口 → 无法补给 → 燃料安全余量风险
- 计划航线穿越通信盲区 → 期间操作离线 → 恢复后校验合并
- 低能见度航段 → 安全航速下降 → 单位油耗上升

## 离线合并语义

进入盲区时记录航路基线；盲区内编辑先做预检（航路点是否已越过、是否穿陆、
是否进入冰带核心），通过后进入「待合并」队列并在画面上临时预览。
恢复通信时系统丢弃草稿、以恢复时刻的真实航路为基线逐项重放：
有效操作被接受并重新计算 ETA；冲突操作被拒绝并在「连锁影响」页给出原因。
